# AI-DLC memory protocol

Normative spec for the opt-in memory extension. The protocol is version-independent: it keys off stage names and artifact paths, not off an AI-DLC product version. Product packaging for a given release lives in `VERSION` and the install guide. This file does not change behavior when the marker below is absent.

The schema is `okf-frontmatter.schema.json` in this directory. Templates live in `templates/` next to the rule-details root.

## Opt-in

The extension is on only when this marker exists:

```text
aidlc-docs/knowledge/.aidlc-memory
```

The marker may be empty, or JSON copied from `templates/aidlc-memory.json`. Presence turns the extension on. A JSON marker with `"enabled": false` turns it off again without deleting the directory. When the extension is off, do not create `knowledge/` or `openspec/`, do not run the memory stages, and follow the workflow exactly as it reads without this extension.

`knowledge/` and `openspec/` live inside `aidlc-docs/`. The workspace rule that documentation belongs only in `aidlc-docs/` stays as it is. Application code stays at the workspace root.

## Bundle layout

```text
aidlc-docs/
├── knowledge/                         # OKF v0.2 bundle
│   ├── .aidlc-memory                  # opt-in marker
│   ├── index.md                       # bundle root; frontmatter is only okf_version
│   ├── log.md                         # append-only history, newest date first, no frontmatter
│   ├── .events.jsonl                  # events from the memory tool
│   ├── code/
│   │   ├── .stale.json                # generated by check; not a concept
│   │   └── *.md                       # codekb entries
│   ├── adr/
│   │   └── *.md
│   └── handoff/
│       └── cycle-NN.md                # NN is at least two digits
└── openspec/
    ├── specs/<capability>/spec.md     # living specs
    └── changes/
        ├── <change-id>/
        │   ├── proposal.md
        │   ├── tasks.md
        │   └── specs/<capability>/spec.md
        └── archive/YYYY-MM-DD-<change-id>/
```

`index.md` is for progressive disclosure. At cycle start the agent reads the latest handoff and `index.md` only, then the check summary. It does not open every codekb entry up front.

## OKF v0.2 profile

Concept files are UTF-8 markdown with YAML frontmatter. `type` is the only field OKF requires. Consumers must keep unknown keys. Timestamps are ISO 8601 with an explicit UTC offset.

Trust:

- `generated.by` and `verified.by` are actors. A human approval uses the prefix `human:`. Agents use `agent:<name>`. Processes use `process:<name>`.
- `verified` is one `{by, at}` mapping or a list of them. The latest `at` is the most recent confirmation.
- No `verified` entry means unverified. A `human:` entry means a person approved that file.

AI-DLC extensions, preserved even though OKF v0.2 does not define them:

| Key | Where | Meaning |
| --- | --- | --- |
| `source_commit` | CodeKB entry, handoff | Full git commit `stamp` wrote. `unversioned` when the workspace has no git. |
| `sources[].path` | CodeKB entry | Workspace-relative path, forward slashes. Hashed by the tool. |
| `sources[].sha256` | CodeKB entry | Lowercase hex SHA-256 of the file after newline normalization to LF. |
| `sources[].resource` | CodeKB entry | OKF-required. For code, the same path as `path`. |
| `covers` | CodeKB entry | Paths, directory prefixes ending in `/`, or globs this entry is responsible for. |
| `derived_from` | any concept | Ids or bundle-relative paths this concept comes from. |
| `aggregate` | CodeKB entry | `true` means the entry document is stale only past `aggregate_ratio`. |
| `re_mode` | handoff | `skip`, `delta`, or `full` for the cycle that produced the handoff. |

`sources[].path` defaults to `resource` when `path` is omitted and `resource` is a relative path. The model never calculates a hash. `aidlc_memory.py stamp` writes `sha256` and `source_commit`.

### CodeKB entries

One entry describes one area of the code. Prefer a narrow entry per source file. Use `aggregate: true` for documents such as an architecture overview whose `sources` list is wide. An aggregate entry is itself stale only when more than `aggregate_ratio` (default 0.30) of its sources diverge, or when a source file is missing. A single divergent source on an aggregate entry is still listed in `.stale.json` and still forces at least delta mode, so a hotfix cannot hide inside a wide entry.

### Handoff

`templates/handoff.md` is the fixed model. These headings are mandatory, in this order: `Escopo`, `Changes`, `Stale`, `Dívidas`, `Pendências`, `Commit`. A cycle is closed only when the handoff has a `verified` actor whose `by` starts with `human:`.

### Index and log

`index.md` follows OKF: the only frontmatter key on the bundle root is `okf_version: "0.2"`. The body is a short linked list.

`log.md` has no frontmatter. Date headings are `## YYYY-MM-DD`, newest first. Entries are bullets. The leading bold word is a label (`Initialization`, `RE`, `Archive`, `Handoff`). Append. Do not rewrite earlier dates.

## Reverse-engineering modes

`aidlc_memory.py check` chooses the mode. The model proposes that mode to the human and does not replace it with its own judgment. The human can still ask for a full scan (`--user-requested-full`, or the same request recorded in the audit).

| Mode | When |
| --- | --- |
| `disabled` | Marker absent, or marker JSON has `enabled: false`. Exit 0. |
| `skip` | Extension on, nothing stale, no uncovered code, no force-full reason. |
| `delta` | Some source is stale or uncovered, and no force-full reason applies. Rescan only those paths and the entries whose status is stale. |
| `full` | A force-full reason applies, or the workspace has code and no codekb yet. Analyze every package. |

Greenfield (no code files match the code extensions, and there is no codekb) is `skip` with reason `greenfield`. Reverse engineering does not run.

### Hash

Read the file as bytes. If the sample contains a NUL, hash the raw bytes. Otherwise normalize newlines to LF (`CRLF` and bare `CR` become `LF`) and hash that. Compare with `sources[].sha256`. A line-ending-only edit is not stale.

SHA-256 is the final word. `git diff` is only a fast filter: when `source_commit` is an ancestor of `HEAD`, hash the sources that appear in `git diff --name-only --no-renames <commit> HEAD`, in `git status --porcelain`, or whose file is missing. When the commit is missing or is not an ancestor, hash every source (rebase, shallow clone, squash).

No git repository: do not force full because a commit is missing. Compare hashes only. `stamp` writes `source_commit: unversioned`.

### What check writes

`aidlc-docs/knowledge/code/.stale.json`:

- `mode`, `reasons`, `head`, `divergence_ratio`
- `entries[]` with `status` of `current` or `stale`, plus `stale_sources` and `noted_sources`
- top-level `stale_sources` and `uncovered`
- `load_estimate` for the latest handoff plus `index.md`, budget 2000 tokens (length divided by 4)

Exit 0 when mode is `disabled` or `skip`. Exit 1 when mode is `delta` or `full`. Exit 2 when the command itself cannot run.

A non-aggregate entry is `stale` when any of its sources diverge or are missing. An aggregate entry is `stale` when a source is missing or the share of divergent sources is greater than `aggregate_ratio`. Divergent sources below that ratio are `noted_sources` and still appear in the top-level `stale_sources` list.

`divergence_ratio` is `(distinct divergent sources + uncovered files) / (distinct known sources + uncovered files)`.

### Force a full scan when any of these hold

Checked on a new cycle. `--resume` suppresses only the two cycle-boundary reasons (`handoff_missing_or_unapproved` and `delta_streak`), because an in-progress cycle has no handoff yet and must not be thrown away. Stale files, unreachable commits, manifests, and unaudited commits still apply on resume.

- `source_commit` absent, or not an ancestor of `HEAD`. Hash comparison still runs.
- `divergence_ratio` greater than `stale_ratio` (default 0.30). Equal to 0.30 stays delta. Uncovered files count in the ratio. They do not, by themselves, force full when the ratio is at or under the threshold.
- A dependency or build manifest changed, or a top-level directory appeared or disappeared. Manifests are matched by file name: `pom.xml`, `package.json`, `package-lock.json`, `build.gradle`, `build.gradle.kts`, `settings.gradle`, `go.mod`, `go.sum`, `Cargo.toml`, `Cargo.lock`, `requirements.txt`, `pyproject.toml`, `Pipfile`, `Gemfile`, `composer.json`, `Makefile`, `Dockerfile`, `docker-compose.yml`, `compose.yaml`, `Package.swift`, `mix.exs`, `pubspec.yaml`, `build.sbt`, and any `*.csproj`.
- The last `max_delta_streak` approved handoffs (default 3) all have `re_mode: delta`.
- A commit since `source_commit` does not appear, by full id or by a 7 or 12 character prefix, in `aidlc-docs/audit.md`.
- A codekb exists and the latest `handoff/cycle-NN.md` is missing or has no `human:` verification.
- The user asked for a full scan.

Code files are the extensions listed in workspace detection (`.java`, `.py`, `.js`, `.ts`, `.jsx`, `.tsx`, `.kt`, `.kts`, `.scala`, `.groovy`, `.go`, `.rs`, `.rb`, `.php`, `.c`, `.h`, `.cpp`, `.hpp`, `.cc`, `.cs`, `.fs`, `.swift`, `.vue`, `.svelte`, `.sql`, `.sh`). Skip `aidlc-docs`, `.git`, `node_modules`, `vendor`, `dist`, `build`, `target`, `__pycache__`, `.venv`, `venv`, and `.tox`. A file is uncovered when it matches those extensions and no entry's `sources` or `covers` claims it. A `covers` entry that ends with `/` is a directory prefix. `*` and `?` are globs.

Renames are compared with `--no-renames`, so the old path goes stale and the new path is uncovered unless some `covers` entry already claims it.

## Human gates

These are blocking. Do not continue past them without the human's answer, and write that answer to `aidlc-docs/audit.md` as the raw input.

1. Cycle start: the human approves `skip`, `delta`, or `full` before reverse engineering. Record `## Memory RE Decision` with `RE Decision`, `Reasons`, `User Input`, and `Approved`.
2. Reverse engineering step 13: the human approves the scan before `stamp`.
3. OpenSpec archive: `archive-apply` refuses to run without `--approved`. Any conflict exits 1 and blocks. The model does not pick a side.
4. Cycle close: the human approves the handoff. Only then add `verified.by: human:...`.

## Cycle shape

Cycle start runs inside Workspace Detection when the marker exists.

- In-progress cycle (state exists, this cycle has no approved handoff yet): resume. Run `check --resume`. Do not open a new cycle.
- Previous cycle closed (latest handoff is human-approved) or there is no state: new cycle. Run `check`. Read the latest handoff and `index.md` only, within the token budget. Ask the human to approve the mode.

Delta reverse engineering re-reads only `stale_sources`, `uncovered`, and entries whose status is `stale`. It does not analyze packages the check calls current. After step 13 is approved, rewrite the in-scope codekb entries and run `stamp` on each. `stamp` updates every present source and then sets `source_commit` to `HEAD`. If a source file is missing, `stamp` changes nothing and exits 1.

Full reverse engineering analyzes every package, then the same stamp step.

Cycle close sits after Build and Test and before Operations, and only when the marker exists.

1. `archive-check` for each open change. On conflict, stop for a human. Do not write the living spec.
2. `archive-apply --approved` only after that approval. Then ingest is done: the living spec has one block per requirement id.
3. `lint` the OpenSpec tree.
4. Update `index.md` and append to `log.md`.
5. Write `handoff/cycle-NN.md` from `templates/handoff.md` and stop for human approval.
6. Append the decision, the archive result, and the handoff approval to `audit.md`.

When the marker is absent, Build and Test continues to Operations as before. There is no cycle close.

## OpenSpec subset

This profile does not call the OpenSpec CLI. One user intent becomes one `changes/<change-id>/` directory. `change-id` is kebab-case.

Living specs use `templates/openspec-spec.md`. Deltas use `templates/openspec-delta.md`. A requirement id is the text of a heading that starts with `### Requirement:`.

Delta sections are `ADDED Requirements`, `MODIFIED Requirements`, `REMOVED Requirements`, and `RENAMED Requirements`.

`archive-check` reports a conflict, and does not edit files, when:

- an ADDED requirement already exists with a different body (`added_exists`)
- a MODIFIED requirement is missing (`modified_missing`)
- a REMOVED requirement is missing (`removed_missing`)
- a RENAMED section is present (`rename_requires_human`)
- a file contains conflict markers (`conflict_markers`)
- two blocks in the same change give the same requirement id different bodies (`duplicate_requirement`)

An ADDED requirement whose body already matches the living spec is `already_present`, not a conflict. `archive-apply` deletes nothing in that case.

`archive-apply --change ID --approved` runs `archive-check` first. On conflict it exits 1 and writes nothing. Without `--approved` it exits 2 and writes nothing. On success it applies ADDED, MODIFIED, and REMOVED, moves the change directory to `changes/archive/YYYY-MM-DD-<id>/`, and appends an `archive` event. It never applies RENAMED. The human turns a rename into a MODIFIED plus a REMOVED, or edits the living spec and drops the RENAMED section, then runs apply again.

Requirements documents and unit plans reference change ids and requirement ids. They do not copy requirement bodies. Each unit records its `change-id` in `aidlc-docs/aidlc-state.md`.

## Tool contract

The tool is `aidlc-rules/tools/aidlc_memory.py`. Python 3 standard library only. The agent looks for it in this order:

1. `.aidlc/aidlc-rules/tools/aidlc_memory.py`
2. `.aidlc/tools/aidlc_memory.py`
3. `aidlc-rules/tools/aidlc_memory.py` under the workspace
4. `tools/aidlc_memory.py` next to the resolved rule-details directory

Commands:

```text
aidlc_memory.py check [--workspace DIR] [--resume] [--user-requested-full]
aidlc_memory.py stamp ENTRY [--workspace DIR]
aidlc_memory.py emit archive --change-id ID --result applied|blocked [--workspace DIR]
aidlc_memory.py emit handoff --cycle N --approved true|false [--workspace DIR]
aidlc_memory.py archive-check --change ID [--workspace DIR]
aidlc_memory.py archive-apply --change ID --approved [--workspace DIR]
aidlc_memory.py lint [--workspace DIR]
aidlc_memory.py manual
```

`check` and `stamp` are the hash boundary. `archive-check` and `archive-apply` are the merge boundary. Events are appended to `aidlc-docs/knowledge/.events.jsonl` as one JSON object per line: `re_decision`, `stale_detected`, `archive`, `handoff`. Each line has `ts` and the fields for that event. `check` prints a short markdown summary on stdout. `--json` prints the result object instead.

## Audit block

```markdown
## Memory RE Decision
**Timestamp**: [ISO-8601]
**RE Decision**: skip|delta|full
**Reasons**: [comma-separated reasons from .stale.json]
**User Input**: "[raw user reply]"
**Approved**: yes|no
```

Every skip, delta, and full decision gets one of these blocks. Cycle close appends `## Memory Cycle Close` with the archive result and the handoff approval.

## Manual fallback

Use this when Python is missing or the script cannot be found. Do not invent hashes.

1. If `aidlc-docs/knowledge/.aidlc-memory` does not exist, stop. Memory is off.
2. Read each `aidlc-docs/knowledge/code/*.md` frontmatter for `source_commit`, `aggregate`, and each source `path` (or `resource`) and `sha256`.
3. `git rev-parse HEAD`. For each distinct `source_commit`, `git cat-file -e <commit>^{commit}` and `git merge-base --is-ancestor <commit> HEAD`. If that fails, hash every source and treat the mode as full.
4. When the commit is an ancestor, list candidates with `git diff --name-only --no-renames <commit> HEAD` and `git status --porcelain`.
5. Hash a text file after deleting CR bytes. `tr -d '\r' < file | sha256sum` matches the tool. A mismatch or a missing file is stale. A new code file that no `path` and no `covers` entry claims is uncovered.
6. Apply the mode table and the force-full list in this document. Write `aidlc-docs/knowledge/code/.stale.json` with the same fields the tool writes.
7. Do not skip reverse engineering when the mode is `delta` or `full`. Ask the human, then record the audit block.

`stamp` by hand: recompute each source hash, write the hex into `sha256`, and set `source_commit` to `git rev-parse HEAD` only after every source file was present.

## Decisions recorded here

- The 30 percent test is `divergence_ratio > stale_ratio`. Uncovered files sit in that ratio. A few uncovered files stay in delta.
- A hotfix is always a divergent or missing source in `.stale.json`, including when the only entry that names the file is an aggregate below its own threshold. Mode is then at least delta.
- `--resume` does not treat a missing handoff as force-full. Starting a new cycle does.
- Identical ADDED bodies are `already_present`. Different bodies conflict.
- RENAMED is never auto-applied.
